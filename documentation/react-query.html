First, two kinds of state

Client state

you own it
  • Is the modal open, what is typed in the box
  • Instant and always correct
  • Only your app can change it

useState is enough

Server state

you only borrow it
  • Lives on a machine you do not control
  • You can only reach it later, over the network
  • Other people change it behind your back

this one needs a cache

The one idea to take home

Your component is holding a snapshot, and that snapshot will get out of date.

So the real question stops being "how do I fetch data" and becomes: how do I hold it, notice when it is stale, and re-sync at the right time?

answering that is a caching system

The server the real, current truth
v3
↑ moved on without telling you
Your component the copy you fetched earlier
v1

Reading data: one hook,
keyed by a name

const { data, isPending, error } = useQuery({
  queryKey: ['todos'],
  queryFn: () => fetch('/api/todos')
              .then(r => r.json()),
})

The queryKey is just an address in the cache. Everyone who asks for the same key shares the same data.

→ caching, request dedup, and sharing, all for free

Caching doesn't stop data
going stale. It tracks it.

Any borrowed copy can be wrong a second after you read it. Nothing can fix that.

So "stale" becomes a label on the cache entry, not a silent problem in your app.

fresh stale 
useQuery({
  queryKey: ['todos'],
  queryFn: fetchTodos,
  // count as fresh for 60s
  staleTime: 60_000,
})

Hitting staleTime does not refetch on its own

It only arms the query. A refetch runs when a trigger fires and the entry is stale right then.

How TanStack Query
makes paging feel instant

Put the page and sort inside the key. Each page becomes its own cache entry.

1
2
3
4
5

Visited pages are cached, so paging back is instant, no request. And keepPreviousData holds the old rows on screen while the next page loads, so the table never flashes empty.

import { keepPreviousData } from
  '@tanstack/react-query'

const { data, isPlaceholderData } =
  useQuery({
    queryKey: ['users', { page, sortBy }],
    queryFn: () => fetchUsers({ page, sortBy }),
    placeholderData: keepPreviousData,
  })

bonus: prefetchQuery the next page so it's ready before they click

So, what did we buy?

It never promises fresh-forever data. It promises your UI stays eventually in sync with the server, and does the syncing for you.

You turn "fetch data" into "cache and sync server state", and the rest follows: less code, fewer bugs, snappy pages.
